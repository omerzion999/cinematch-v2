# CineMatch AI v2 - Design Spec
תאריך: 2026-06-10

## רקע ומטרה

זהו פרויקט גמר אקדמי (workshop AI/ML) - שדרוג של פרויקט קיים (`cinematch-ai-main`, להלן **v1**) שהוא אפליקציית Streamlit להמלצת סדרות טלוויזיה.

**v1 כבר כולל** (ונשמר/מורחב ב-v2):
- מאגר נתונים נקי: 11,013 סדרות, 22 עמודות (`data/catalog.parquet`), כולל `genres`, `rating`, `overview`, `poster_path`, `num_seasons`, `decade`, ציוני z מנורמלים וכו'.
- Embeddings מחושבים מראש (`data/embeddings.npy`, 11,013×384, sentence-transformers multilingual)
- מנוע המלצות היברידי: Jaccard (ז'אנר/עידן/שפה) + Cosine numeric (rating/votes/year/popularity) + Cosine text (embeddings)
- זיהוי אנומליות (anomaly detection) על בסיס percentile threshold
- אינטגרציית LLM (Groq, fallback Anthropic) ל-intent parsing, הסברים, ושיחה (`chat_turn`)
- i18n דו-לשוני (עברית/אנגלית, RTL/LTR)

**v2 משדרג** את חווית המשתמש ל-**אפליקציית צ'אט בסגנון וואצאפ** (React/TypeScript), תוך שימוש חוזר מקסימלי בלוגיקת ה-ML/NLP הקיימת מ-v1, ותוספת שכבת **K-Means clustering** חדשה.

### דרישות אקדמיות רלוונטיות
המטלה דורשת שילוב של "מודלים לזיהוי דמיון, clustering, או המלצות" + "כלי AI לאיתור דפוסים/מגמות/אנומליות" + "מערכת שפה טבעית לניתוח טקסט חופשי". v1 כבר מכסה דמיון+המלצות+אנומליות+NLP; **v2 מוסיף clustering (K-Means)** ובכך מכסה את כל שלושת הנושאים המרכזיים. הכי חשוב למשתמש: **שיהיה אייג'נט שאפשר באמת להריץ** (לא רק קוד/מחקר).

**דיפלוי:** Render.com, שירות יחיד (Python/FastAPI), כפי שהקולג' ממליץ ("אפשר להעלות קוד פייתון לגיט ולהשתמש ב-Render"). אונליין לשימוש אישי, **ללא הגנת סיסמה**.

## שכבת הנתונים וה-Clustering (K-Means)

**שלב הכנה (חד-פעמי, offline, לא בזמן ריצה):**
- סקריפט `clustering/train_clusters.py` מריץ K-Means על כל 11,013 הסדרות, לפי וקטור פיצ'רים: ז'אנרים (multi-hot/top genres), `rating_z`, `votes_z`, `popularity_z`, `start_year_z`, `num_seasons` (מנורמל).
- בחירת k באמצעות Elbow method / Silhouette score (k צפוי בטווח ~8-12).
- פלט: `data/cluster_labels.parquet` (title → cluster_id) + `cluster_profiles.json` (תיאור טקסטואלי לכל קלאסטר, למשל "דרמות מתח אפלות מהעשור האחרון").

**בזמן ריצה:**
- 5 תשובות ה-onboarding ממופות לאותו וקטור פיצ'רים → קלאסטר הכי קרוב (מרחק לצנטרואיד).
- בתוך הקלאסטר הנבחר, מנוע ההמלצות ההיברידי (Jaccard + Cosine numeric, מ-v1) מדרג ובוחר 3 סדרות.
- "תיאור הקלאסטר" יכול להיות חלק מתשובת הבוט ("אתה בטעם של: ...").

## זרימת המשתמש (UX)

1. **הודעת פתיחה** (אוטומטית): הצגה עצמית + שני כפתורים:
   - "כן, בוא נתחיל" → שלב 2
   - "לא תודה, אני רוצה להתקדם לצ'אט הרגיל" → דילוג ישיר לשלב 5

2. **5 שאלות onboarding**, אחת בכל פעם, כבועת בוט עם כפתורי בחירה (נסגרת אחרי בחירה, כמו וואצאפ):
   1. ז'אנר מועדף - דרמה / קומדיה / אקשן-מתח / מד"ב-פנטזיה / פשע / אנימציה / רומנטיקה / לא משנה
   2. אורך - קצר/מיני (1-2 עונות) / בינוני (3-5) / ארוך (6+) / לא משנה
   3. עידן - חדש (2020+) / קלאסי / לא משנה
   4. טון - קליל ומשעשע / רציני ודרמטי / מותח ואקשן / לא משנה
   5. פופולריות - להיטים מוכרים / פנינים נסתרות / לא משנה

3. **עיבוד:** מיפוי ל-cluster → מנוע היברידי בוחר 3 סדרות.

4. **הצגת תוצאות:** בועת בוט עם 3 כרטיסי המלצה (פוסטר, שם, ז'אנר, דירוג). לחיצה על כרטיס → מודאל/פופאפ עם:
   - כל הפרטים מהקטלוג (תקציר מלא, עונות, שנה, שפה, דירוג, ציון התאמה)
   - הסבר קצר מה-LLM ("למה המלצנו על זה")
   - מידע חי מ-TMDB (טריילר, שחקנים ראשיים, איפה לצפות) - נטען בלחיצה בלבד

5. **הודעת סיום + מעבר לצ'אט פתוח:** "מקווה שאהבת את ההמלצות! ..." ואז שיחה חופשית.

6. **צ'אט פתוח (combination mode, כמו `chat_turn` ב-v1):** ה-LLM מזהה האם המשתמש מבקש המלצות נוספות/סינון (`search`/`refine`), שאלה על סדרה ספציפית מהמאגר, או סתם שיחה כללית - ומגיב בהתאם.

7. **שמירת מצב:** היסטוריית השיחה נשמרת ב-`localStorage` של הדפדפן (לא בשרת). רענון עמוד לא מאפס; דפדפן/מחשב אחר = שיחה חדשה.

## LLM (Groq) ו-TMDB

**Groq** משמש ל:
- כתיבת הסבר קצר (1-2 משפטים) לכל אחת מ-3 ההמלצות
- ניהול שיחה חופשית (`chat_turn`): סיווג כוונה (chat/search/refine/show-info), זיהוי שפה (עברית/אנגלית) ותגובה באותה שפה
- **לא** משמש לשאלות ה-onboarding עצמן (כפתורים קבועים, דטרמיניסטי)

**TMDB:**
- תמונות: `poster_path` קיים בקטלוג → `https://image.tmdb.org/t/p/w342{poster_path}`
- קריאות חיות (לפי שם+שנה, רק בלחיצה על כרטיס): טריילר, שחקנים, פלטפורמות צפייה - דורש `TMDB_API_KEY`

## API (FastAPI)

| Endpoint | תפקיד |
|---|---|
| `POST /api/recommend` | 5 תשובות onboarding → cluster + 3 המלצות + הסברים |
| `POST /api/chat` | הודעה חופשית + היסטוריה → תגובת בוט (+ המלצות חדשות אם רלוונטי) |

## i18n

ברירת מחדל: עברית (RTL). מתג מעבר לאנגלית בכותרת הצ'אט (כמו v1). שיחה חופשית עוברת אוטומטית לשפת הכתיבה של המשתמש.

## בדיקות והערכה

- **K-Means:** דוח Elbow/Silhouette לבחירת k (תורם גם לדו"ח האקדמי)
- **מנוע המלצות:** המשך שימוש במדדי ההערכה הקיימים מ-v1 (Spearman, Agreement@10, Precision@5) - סקריפט נפרד, לא חלק מהאפליקציה הרצה
- **קצה-לקצה:** בדיקה ידנית של זרימת onboarding מלאה + תרחישי שיחה חופשית (בדומה ל-`tests/test_cases.py` ב-v1)
- בסיום הפיתוח: הרצת האתר בדפדפן ווידוא שהזרימה המלאה עובדת (onboarding → המלצות → פופאפ → שיחה חופשית)

## מחוץ ל-Scope

- חשבונות משתמשים / הגנת סיסמה
- שמירת שיחות בצד שרת (DB)
- עדכון/הרחבת מאגר הנתונים (משתמשים בקטלוג הקיים מ-v1 כמות שהוא)
- אפליקציית מובייל ייעודית (רק אתר רספונסיבי)
- כתיבת הדו"ח/מצגת האקדמיים (שלב נפרד לאחר שהאייג'נט פועל)

## הערות יישום / מקרי קצה

- **`num_seasons`/`num_episodes` חסרים** (NaN עבור מקורות שאינם TMDB): להשלים בערך median של המאגר לצורך חישוב ה-clustering, כדי שלא ישפיעו לרעה על המרחק.
- **תשובת "לא משנה"** באחת משאלות ה-onboarding: הפיצ'ר המתאים באותה שאלה לא נכלל בחישוב המרחק לקלאסטר (ולא מקבל ערך שרירותי).
- **TMDB live lookup ללא תוצאה תואמת** (שם+שנה לא נמצאו): הפופאפ מציג את נתוני הקטלוג הקיימים בלבד (פוסטר/תקציר/דירוג), בלי טריילר/שחקנים - ללא שגיאה למשתמש.
- **כל 5 התשובות "לא משנה"**: ברירת מחדל - הקלאסטר עם ה-`binge_fit_score` הממוצע הגבוה ביותר (הסדרות "הכי בטוחות"/הכי מומלצות באופן כללי).

## כיווני המשך אפשריים (לדו"ח / עתיד)

- הוספת collaborative filtering אם ייאספו נתוני משוב משתמשים בפועל
- הרחבת ה-clustering להציג למשתמש ויזואליזציה של הקלאסטרים (t-SNE/PCA)
- שיפור ה-anomaly detection לזיהוי בקשות שלא ניתן למלא מהמאגר
